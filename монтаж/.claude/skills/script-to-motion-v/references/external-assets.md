# Внешние ассеты в бролах

Когда деталь дорого/невозможно нарисовать кодом — фотореализм, текстуры, отражения, «живой» органичный моушн — её берут готовым файлом и кладут слоем в Remotion. Источники: AI-генерация (Runway/Kling/Sora/Luma и т.п.), скачанные клипы/анимации, фото, картинки. Remotion работает как компоновщик: ассет = нижний слой, код-графика и субтитры — поверх. Итоговый mp4 непрозрачен.

## Где лежат файлы

Одна подпапка на бролл, имя совпадает со slug композиции:

```
public/assets/<slug>-<NN>-<mode>/
  bg.mp4          # фоновый клип (непрозрачный)
  overlay.webm    # прозрачная анимация поверх сцены (alpha)
  photo.jpg       # фото / картинка
  BRIEF.md        # что за ассеты нужны (коммитится; бинарь — нет)
```

Доступ из композиции — только через хелпер:

```ts
import { asset } from '../../assets';
asset('claude-free-03-full', 'overlay.webm'); // → staticFile('assets/claude-free-03-full/overlay.webm')
```

`.gitignore` игнорит сам медиа-бинарь (`*.mp4/*.mov/*.webm/*.png/*.jpg/*.mp3/...`), но `BRIEF.md` и структура остаются в репозитории.

## Общая библиотека переиспользуемых исходников — `lib()`

Логотипы брендов/инструментов и прочие материалы, нужные **не одному** броллу, по папкам не дублируй — бери из общей библиотеки `public/library/`:

- доступ — хелпер `lib(path)` (`src/assets.ts`), путь относительно `library/`:
  ```ts
  import { lib } from '../../assets';
  <Img src={lib('logos/anthropic/claude-logo.png')} />
  <AssetImage src={lib('logos/google/gemini.png')} fit="contain" />
  // data-driven список: в поле file держи путь относительно library/
  ```
- раскладка по вендору: `logos/anthropic/`, `logos/google/`, `logos/competitors/`;
- происхождение каждого файла — `public/library/manifest.json`; что есть и как добавлять — `public/library/README.md`;
- в отличие от `public/assets/**`, файлы библиотеки **коммитятся в git** (маленькие, стабильные).

Прежде чем скачивать/генерировать логотип в папку бролла — проверь, нет ли его уже в `public/library/logos/`. Переиспользуемый материал добавляй в библиотеку (с записью в `manifest.json`), а не в папку конкретного бролла. `asset(slug, file)` остаётся для **одноразовых** ассетов сцены, `lib(path)` — для общего.

## Два способа подать ассет

**(a) Ad-hoc — пользователь присылает файл.** «Вот анимация искр, наложи на бролл #03» / «используй это фото как фон». Тогда:
1. Положи файл в `public/assets/<slug-NN>/` (осмысленное имя: `overlay.webm`, `bg.mp4`, `photo.jpg`).
2. Вшей нужный примитив в сцену бролла.
3. Проверь формат (особенно альфу — см. ниже), при несоответствии скажи пользователю, что переэкспортировать.

**(b) Декларативно в Notion — токены в маркере.** В правой колонке после метки бролла (`бролл` / `бролл половина` / `бролл фулл`) идут токены ассетов (см. парсинг). Тогда при генерации сразу подключаешь примитивы и пишешь `BRIEF.md` на недостающие файлы + плейсхолдер, чтобы typecheck/Studio не падали.

## Грамматика токенов (для Phase 2 парсинга)

После метки бролла (`бролл` / `бролл половина` / `бролл фулл`) в маркере могут идти токены (в любом порядке, до творческого `extraInstructions`):

| Токен | Слой | Примитив |
|---|---|---|
| `фон:<file>` | базовый медиа-слой (видео или картинка по расширению) | `AssetVideo` / `AssetImage` |
| `оверлей:<file>` | прозрачное видео поверх сцены | `AssetVideo transparent` |
| `фото:<file>` | статичная картинка (с Ken Burns) | `AssetImage` |

Токенов может быть несколько. Остаток текста после токенов — это `extraInstructions` (творческое указание), его приоритет над архетипом сохраняется как обычно.

Примеры строк таблицы:
```
бролл половина (оверлей: sparks.webm — искры поверх кода, светлый стиль)
бролл (фон: city.mp4 — город, поверх крупный заголовок Ollama)
бролл (фото: chip.jpg — макрофото чипа, медленный zoom)
```

Парсинг: расширение определяет тип (`.mp4/.mov/.webm` → видео, `.jpg/.png/.webp` → картинка). Имя файла из токена → ожидаемый путь `public/assets/<slug-NN>/<file>`.

## Требования к форматам

| Тип ассета | Формат | Примечание |
|---|---|---|
| Прозрачный оверлей (альфа) | **WebM VP8/VP9 alpha** или **ProRes 4444 `.mov`** | h264/обычный mp4 альфу НЕ несёт |
| Непрозрачный клип | mp4 (h264/h265/av1) | — |
| Фото / картинка | png / jpg / webp | под full — портрет ≥1080×1920; под half — ≥1080×960 в top-зону |
| Звук (опц.) | mp3 / wav | — |

`transparent` извлекает кадры как PNG → рендер чуть медленнее (ожидаемо для коротких бролов).

## Сниппеты подключения

```tsx
import { AssetVideo } from '../../components/AssetVideo';
import { AssetImage } from '../../components/AssetImage';
import { asset } from '../../assets';

const SLUG = 'claude-free-03-full';

// Фон-фото с Ken Burns + прозрачный оверлей + код-подпись поверх
<AbsoluteFill>
  <AssetImage src={asset(SLUG, 'photo.jpg')} kenBurns={{ from: 1, to: 1.12, panY: -30 }} fadeIn={6} />
  <AssetVideo src={asset(SLUG, 'overlay.webm')} transparent fadeIn={6} fadeOut={8} />
  {/* …код-графика и субтитры… */}
</AbsoluteFill>
```

## Удаление монотонного фона (чёрный / белый)

Часто скачанный клип/анимация идёт **без альфы, на сплошном чёрном или белом фоне** (свечения, искры, дым, огонь, частицы, леттеринг). Два пути убрать фон:

**1. CSS blend (встроено, без препроцессинга) — рекомендованный путь.** Проп `blend` у `AssetVideo`:
- `blend="screen"` — убирает **чёрный** фон (чёрное → «прозрачно», светлый контент проходит). Для свечений/искр/дыма/огня на чёрном.
- `blend="multiply"` — убирает **белый** фон (белое → «прозрачно», тёмный контент остаётся). Для тёмного леттеринга/линий на белом.

```tsx
// клип «эффект на чёрном фоне» — чёрное выбивается
<AssetVideo src={asset(SLUG, 'sparks-on-black.mp4')} blend="screen" />
```

Ограничение: это **смешивание со слоем ниже, не настоящий альфа-кей**. Цвета взаимодействуют с фоном (screen осветляет, multiply затемняет), полупрозрачные края и средние тона передаются приближённо. Для ярких эффектов на чистом чёрном/белом выглядит как чистый кей; для контента с важными точными цветами — нет.

**2. Настоящий альфа-кей (точный, но нужен системный ffmpeg).** Бандл-ffmpeg Remotion собран с `--disable-filters` — `colorkey`/`chromakey`/`lumakey` в нём **нет**. Чтобы запечь альфу в WebM, нужен системный ffmpeg (`brew install ffmpeg`):

```bash
# чёрный фон → прозрачный WebM (lumakey по яркости)
ffmpeg -i clip.mp4 -vf "lumakey=threshold=0.05:tolerance=0.1,format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 clip.webm
# затем как обычный прозрачный оверлей:  <AssetVideo src=... transparent />
```

Лучший вариант всё же — получить ассет уже с альфой из источника (многие стоки/генераторы отдают WebM/MOV с прозрачностью).

## Плейсхолдер (пока файла нет)

Если ассет ещё не подложен, рисуй залитый бокс с подписью имени файла — чтобы typecheck и Studio работали:

```tsx
<AbsoluteFill style={{ background: '#1e1b4b', alignItems: 'center', justifyContent: 'center' }}>
  <div style={{ color: '#94a3b8', fontSize: 32 }}>asset: overlay.webm</div>
</AbsoluteFill>
```

## half-top + прозрачный оверлей

В half-моде ассет-оверлей держи в зоне top `[0, 960]` (как и всю графику). Фон композиции всё равно заливает весь канвас 1080×1920 — итоговый mp4 непрозрачен, нижняя половина перекрывается лицом ведущего в монтаже (см. «Half-top safe zone» в SKILL.md). Прозрачность оверлея — только относительно слоёв бролла, не выходного файла.

## Чеклист «как передать ассет ассистенту»

1. Назови бролл (номер из storyboard или slug).
2. Скажи роль: фон / прозрачный оверлей / фото.
3. Для прозрачного — экспортируй в WebM VP9 alpha или ProRes 4444 .mov (h264 альфу теряет).
4. Пришли файл или положи его в `public/assets/<slug-NN>/`.
5. После подкладки: `npm run typecheck` → `npm run studio` (проскрабить) → `npm run render <id> out/<id>.mp4`.
