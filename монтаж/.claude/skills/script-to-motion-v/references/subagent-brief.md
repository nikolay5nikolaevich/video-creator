# Контракт субагента-монтажёра (один бролл)

Этот файл читает **субагент**, которому главный агент поручил собрать **ровно один** бролл вертикальной серии. Главный агент уже прочитал сценарий из Notion, собрал комментарии строк с референсами, распарсил всё, согласовал storyboard с пользователем, сохранил картинки-референсы в файлы и создал общую тему серии. Твоя зона ответственности узкая и изолированная: превратить **одну** согласованную storyboard-запись в готовую Remotion-композицию в своей папке — и больше ничего.

Почему так: броллы серии независимы (каждый — отдельная папка `src/animations/<slug>/`), поэтому их монтаж распараллелен по субагентам. Это работает только если каждый субагент строго держится своей папки и общих правил — иначе серия «поплывёт» стилистически или субагенты затрут работу друг друга.

## Что тебе передал главный агент (спецификация бролла)

В промпте ты получишь:

- `slug` — полное имя папки и `id` композиции, например `claude-code-free-03-full`. Используй его как есть, не придумывай своё.
- `mode` — `full` или `half` (half-top).
- `text` — реплика, которую ведущий произносит под этот бролл. Это **смысл, который надо усилить графикой**, а НЕ текст для вывода на экран дословно (см. правило «не дублируй текстом» в SKILL.md).
- `archetype` — выбранный в storyboard архетип (big-number / before-after / bullet-stagger / key-statement / diagram-with-arrows / code-block / …).
- `durationInFrames` и `fps` (30) — длительность уже посчитана, не пересчитывай.
- `visualDescription` — краткое описание сцены из согласованного storyboard. Это твоё ТЗ.
- `extraInstructions` — указание пользователя из маркера и/или комментария Notion на строке (или `null`). **Приоритетнее архетипа и дефолтов темы.** Если есть — реализуй буквально.
- `referenceImages` — список путей к **сохранённым файлам-референсам** из комментария Notion (главный агент уже скачал вложения на диск; или пусто), с ролью каждого:
  - роль `референс` — открой файл через `Read`, считай композицию / палитру / идею / персонажа и **воспроизведи кодом** (по умолчанию; см. Visual quality rule 5 в SKILL.md). Файл в композицию не кладёшь.
  - роль `ассет` — файл вставляется в композицию как есть через `AssetImage`/`AssetVideo` (см. `references/external-assets.md`).
- `assets` — список внешних ассетов `{ kind: 'фон'|'оверлей'|'фото', file, path }` (или пусто).
- `theme` — путь импорта общей темы серии (`../../shared/<base>-theme`) и перечень того, что она экспортит (COLORS, FONTS, FPS, half-хелперы и т.п.). **Тема уже создана главным агентом — только импортируй, не создавай и не редактируй её.**
- `paths` — абсолютные `SKILL_DIR` (корень этого скилла) и `REPO_ROOT` (корень проекта). Пути ниже даны относительно них.

## Прочитай перед тем, как писать код

Эти правила — единый стандарт серии; без них твой бролл выпадет из общего стиля. Читай относительно `SKILL_DIR`:

1. `SKILL.md` — секции **Project conventions**, **Visual quality rules**, **Half-top safe zone**, **Side padding / safe area**, **File structure conventions**, **Verification gotchas**. Это нормативная часть, ей подчиняешься.
2. `references/remotion-api.md` — точные сигнатуры `interpolate` / `spring` / `Sequence` и т.п.
3. `references/visual-archetypes.md` — раздел про твой архетип: как его правильно анимировать.
4. `references/external-assets.md` — **только если** в спецификации есть `assets` или `referenceImages` с ролью `ассет`.

Не читай разделы про Notion, парсинг, style intake, storyboard — это работа главного агента, не твоя.

Посмотри 1 образец того же класса, чтобы попасть в идиоматику репозитория: `src/animations/hello-world/` (минимум), `src/animations/mcp-five-servers/` (мульти-сцены через `<Sequence>`).

**АВТОРСКИЕ НАДПИСИ — ПО-РУССКИ, ИНТЕРФЕЙС — КАК В ЖИЗНИ.** Аудитория русскоязычная. Всё, что ты пишешь **как автор кадра**, пишется на русском: заголовок сцены, eyebrow-кикер, подписи к элементам, поясняющие лейблы, чипы, подписи узлов схемы. Если референс англоязычный — берёшь из него **композицию**, а надпись переводишь; референс это макет, а не источник текста. **Но то, что изображает реальный интерфейс, не переводится**: содержимое окна терминала, Claude Code TUI, UI-панели продукта, строки автодополнения команд — терминал по-русски выглядит фальшиво. Никогда не переводятся названия брендов/продуктов (Claude Code, Gemini, Kimi, GLM, GitHub), команды (`/commit`, `git commit -m`), пути к файлам, код, технические токены. Граница: **это надпись от меня зрителю или то, что написано на экране у героя?** Первое — русский, второе — оригинал. Учти, что русский на 10–20% длиннее: проверь, что переведённый заголовок влезает в safe-area. Подробности и примеры — правило 6 в **Visual quality rules** (`SKILL.md`).

**Готовые лого/маскоты — из библиотеки, не рисуй кодом.** Если по `visualDescription`/`extraInstructions` в кадре нужен узнаваемый бренд-знак или маскот (маскот Claude Code, инструмент, бренд, конкурирующая модель) — **не** воспроизводи его пиксель-артом/SVG вручную. Сначала проверь `public/library/logos/**` (реестр — `public/library/manifest.json`): маскот Claude Code = `logos/anthropic/claude-logo.png`, бренды — `logos/brands/`, конкуренты (Kimi/GLM/Codex/Cursor…) — `logos/competitors/`, Google — `logos/google/`. Нашёл — вставляй **файлом**: `import { lib } from '../../assets'` → `<Img src={lib('logos/anthropic/claude-logo.png')} />`; для маскота Claude Code есть готовый компонент `import { ClaudeCodeLogo } from '../../shared/claude-code-logo'`. Нет в библиотеке — верни это главному агенту (он досорсит настоящий лого и положит в библиотеку), сам пиксель-арт не рисуй. Код рисуй только для generic-иконок без канонического знака (папка, шестерёнка, ноутбук). Тем же путём проверяй любой переиспользуемый исходник — не строй с нуля то, что уже лежит в `public/library/`.

## Алгоритм сборки

1. **Загляни в общую тему.** Прочитай `src/shared/<base>-theme.ts` (путь из `theme`), чтобы знать доступные токены (COLORS, FONTS, half-хелперы) и опираться на них, а не вводить свои цвета/отступы. Единая тема — главный механизм визуальной связности серии.
2. **Изучи референсы.** Для каждого `referenceImages` — открой файл через `Read` и пойми, что из него берёшь (композиция / палитра / персонаж / конкретный объект — главный агент подсказал в `note`). Роль `референс` — воспроизводи кодом по мотивам, не пиксельно; роль `ассет` — вставь файлом. Сцена должна строиться на референсе, а не «по мотивам архетипа с референсом на полке».
3. **Проверь имя на коллизию.** `ls src/animations/` — папки `slug` быть не должно. Если вдруг есть (главный агент пишет, что не должно) — не перезаписывай, верни ошибку главному агенту.
4. **Создай папку `src/animations/<slug>/`** и в ней файлы по сложности сцены (см. File structure conventions):
   - минимум: `index.ts` + `Animation.tsx`;
   - средне: + `Card.tsx` + `data.ts`;
   - сложно (несколько под-сцен): `index.ts` + `Root.tsx` + `Scene*.tsx`, склейка через `<Sequence>`.
   - Запрещены подпапки внутри композиции — бандлер их игнорирует.
5. **`index.ts`** — `defineAnimation` с default export:
   ```ts
   import { defineAnimation } from '../../animation';
   import { FPS, HALF } from '../../shared/<base>-theme';
   import { Animation } from './Animation';

   export default defineAnimation({
     id: '<slug>',
     component: Animation,
     durationInFrames: <durationInFrames>,
     fps: FPS,
     width: HALF.width,   // full и half: 1080
     height: HALF.height, // full и half: 1920 (half — это half-TOP внутри 1920, см. ниже)
   });
   ```
   Для `full` без half-хелперов можно `width: 1080, height: 1920` напрямую.
6. **Компонент** — чистый Remotion (`interpolate`/`spring`/`useCurrentFrame`/`useVideoConfig`/`AbsoluteFill`/`Sequence`). Реализуй `visualDescription`, подчинись `extraInstructions` если есть, опирайся на просмотренные референсы. Палитру/шрифт бери из темы.
7. **Если `mode = half`** — это half-top: композиция всё равно 1080×1920, фон заливает весь канвас, **вся графика только в верхней половине [0, 960]**, значимые элементы в `[60, 880]`. Нижняя половина — тот же фон без графики (там лицо ведущего). Активные эффекты оберни в `overflow: hidden; height: 960`. Полная спецификация — секция «Half-top safe zone» в SKILL.md, не отклоняйся от неё.
8. **Если есть `assets` или картинка-`ассет`** — подключай через `AssetVideo`/`AssetImage` из `src/components/` и `asset('<slug>', '<file>')` из `src/assets.ts`. Порядок слоёв: фон → ассет → код-графика → субтитры. **Если файла нет** по `path` — нарисуй плейсхолдер (залитый бокс с подписью имени файла) и запиши `public/assets/<slug>/BRIEF.md` (что за ассет, целевой путь, формат). Детали — `references/external-assets.md`.
9. **Самопроверка** (см. чек-лист ниже), затем верни отчёт главному агенту.

## Жёсткие контракты изоляции (нарушение ломает параллельную сборку)

- **Пиши только в свою папку** `src/animations/<slug>/` и, при ассетах, в `public/assets/<slug>/`. Не трогай чужие броллы, `src/Root.tsx`, `src/shared/*`, `src/components/*`, `src/assets.ts`, `src/animation.ts`.
- **Не создавай и не редактируй общую тему** — она уже есть, только импортируй.
- **Не запускай** `npm run typecheck`, `npm run studio`, `npm run render` — глобальный typecheck и проверку в Studio делает главный агент один раз после всей сборки. Параллельные запуски только мешают друг другу.
- **Default export** в `index.ts` обязателен (иначе авто-регистрация в `Root.tsx` падает).
- **`id` = имя папки = `slug`**, kebab-case, уникален. Дубликат уронит `Root.tsx` на старте всей серии.
- **Не спрашивай пользователя ничего** — ты неинтерактивен. Любую неоднозначность реши разумным дефолтом в духе спецификации и отметь её в отчёте.

## Чек-лист самопроверки (пройди перед возвратом)

- [ ] Папка названа ровно `slug`; `id` в `index.ts` совпадает с именем папки; есть default export.
- [ ] `durationInFrames`/`fps` совпадают со спецификацией.
- [ ] Все `interpolate` — с `extrapolateLeft/Right: 'clamp'` (иначе мерцание до старта/после конца).
- [ ] Координаты в пределах канваса; для `half` — вся графика в `[0, 960]`, нижняя половина чистая.
- [ ] Текст крупный (заголовок ≥80px full / ≥60px half), мелкого текста нет — кроме явно согласованных терминал/UI сцен.
- [ ] Смысл реплики **не продублирован** подписью, если графика и так его передаёт.
- [ ] Видимое движение во всём диапазоне (entry-spring + что-то ещё), без статичных «замёрзших» секунд.
- [ ] Цвета/шрифт из общей темы (или из `extraInstructions`, если она перекрывает дефолт).
- [ ] Все `referenceImages` просмотрены через `Read`; роль `референс` — воспроизведены кодом (не вставлены файлом), сцена строится на них.
- [ ] `import type { CSSProperties } from 'react'` — если используешь тип.
- [ ] Не тронуты файлы вне своей папки.

## Формат отчёта главному агенту

Верни **кратко** (это пойдёт в общий отчёт серии, без «воды»):

```
#<NN> <slug> — готов
Файлы: index.ts, Animation.tsx[, data.ts, …]
Архетип/визуал: <одна строка — что на экране>
Референсы: нет | воспроизведены кодом (N шт) | вставлен файлом: <file>
Ассеты: нет | нужны файлы: public/assets/<slug>/overlay.webm (бриф записан)
Заметки/риски: <если что-то решил дефолтом, есть мелкий текст, или сцена спорная — иначе «—»>
```

Если собрать бролл не удалось (коллизия имени, противоречивая спецификация, нечитаемый референс) — не выдумывай, верни честно: что пошло не так и чего не хватает.
