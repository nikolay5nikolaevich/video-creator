# Чтение комментариев Notion (референсы к строкам таблицы)

В вертикальном пайплайне маркер бролла живёт в правой колонке таблицы — комментарии его **не заменяют**. Комментарий — это **дополнительный канал указаний к помеченной строке**: пользователь выделяет текст в ячейке (обычно ячейку с меткой `бролл` / `бролл половина` / `бролл фулл`) и оставляет комментарий, где текст — описание анимации, а вложения-изображения — **визуальные референсы** того, как должна выглядеть сцена. Если на помеченной строке есть комментарий — его обязательно считать и реализовать сцену на его основе. Здесь — как достать комментарии через Notion MCP, как привязать их к строкам и что делать, если что-то не пришло.

## Что нам нужно от Notion

Для каждой помеченной строки таблицы:
- id блока строки (`table_row`) или id записи database — чтобы связать комментарий с конкретной строкой;
- `comments[]` — комментарии строки: для каждого текст и вложения (файлы-картинки).

## Как достать комментарии и вложения — два разных канала

Ключевой момент: **текст комментариев и файлы вложений приходят из разных источников.** Hosted-коннектор Notion (`mcp__claude_ai_Notion__notion-fetch` / `notion-get-comments`) **не отдаёт сами файлы вложений** — только факт их наличия (`image-attached-count`). Сами картинки тянет отдельный локальный MCP-сервер **`notion-comment-files`** (инструмент `get_comment_attachments`): он ходит в официальный REST API Notion и **скачивает вложения на диск**.

### Канал A — текст, маркеры, привязка к строкам (hosted-коннектор)
1. **`notion-fetch` страницы/таблицы** (`include_discussions: true`) — структура таблицы, текст строк, маркеры в правой колонке, и какие строки несут комментарии/вложения (`image-attached-count`, `discussion-urls` с `block_id` строки).
2. **`notion-get-comments`** (или аналог в текущем коннекторе; имена тулзов меняются — посмотри ToolSearch по `notion comment`) — текст комментариев помеченных строк и их привязка к `block_id` строки (`table_row`).

Отсюда ты знаешь: какие строки помечены, текст их комментариев и **у каких есть вложения**.

### Канал B — сами файлы вложений (`notion-comment-files`)
Если хотя бы у одной помеченной строки `image-attached-count ≥ 1`, вызови `get_comment_attachments`:

```
get_comment_attachments({ page_url: "<URL страницы>" })          // обойдёт всю страницу
// или точечно и быстрее, если уже знаешь block_id помеченных строк:
get_comment_attachments({ block_ids: ["<table_row block_id>", …] })
```

Возвращает манифест: по каждому комментарию — `block_id`, `discussion_id`, `comment_id`, `comment_text`, и `attachments[].saved_path` (файл **уже скачан** на диск, временный signed-URL Notion отработан сразу). Привяжи `saved_path` к строке по `block_id` (если на блоке несколько дискуссий — уточни по `discussion_id`/`comment_id`). `saved_path` — это и есть твой скачанный референс: `Read` его перед составлением storyboard, а в Phase 5.1 скопируй в слот бролла `public/assets/<slug-NN>/ref-<K>.<ext>`.

### Фолбэк — спросить пользователя
Если `notion-comment-files` недоступен (project-MCP не загружен — нужен перезапуск Claude Code; либо не настроены токен/доступ интеграции) — `get_comment_attachments` либо отсутствует в сессии, либо вернёт ошибку (`401`/`403`/`404`). Тогда **остановись и сообщи пользователю**: вложения комментариев hosted-коннектор не отдаёт; попроси прислать нужные картинки **прямо в чат** (придут в `~/.claude/image-cache/<id>/N.png`) либо настроить сервер (`tools/notion-comment-files/README.md`). Текст комментариев и логику маркеров при этом бери из Канала A — она работает и без сервера. Не угадывай содержимое референса.

## Привязка комментария к строке

- Комментарий, оставленный на выделении внутри ячейки, в API привязан к блоку `table_row` (или к записи database). Сопоставляй по id блока строки.
- Текст бролла (для pacing и смысла сцены) — это по-прежнему **левая ячейка строки**, mode — **метка в правой**. Комментарий задаёт только _как рисовать_.
- **Комментарии учитываются только на помеченных строках.** Комментарий на строке без метки — рабочая заметка, игнорируй (бролл по нему не делаем).

## Текст комментария и инструкция маркера

У помеченной строки могут быть одновременно: инструкция в хвосте маркера (`бролл половина (…)`) и текст комментария. Объедини их в общий `extraInstructions`:

- Оба источника обязательны к исполнению — это per-row указания пользователя, они приоритетнее архетипа и дефолтов style intake.
- При прямом противоречии приоритет у **комментария** — он обычно создаётся позже и детальнее.
- Пустой текст комментария (только картинки) — нормально: `extraInstructions` остаётся из маркера (или null), а картинки идут в `referenceImages`.

## Вложения комментария (изображения)

- Собери все картинки комментария в `referenceImages` строки.
- **Роль по умолчанию — `референс`**: воспроизводишь похожее кодом (композиция / палитра / идея / персонаж), файл в композицию не кладёшь. Не копируй пиксельно (Visual quality rule 5).
- **Роль `ассет`** — только если в тексте комментария или маркера явно сказано «вставь / используй как фон / как фото / как есть». Тогда файл подключается через `AssetImage`/`AssetVideo` (см. `references/external-assets.md`).
- Файлы уже скачаны сервером `notion-comment-files` — бери `saved_path` из манифеста (Канал B выше). В Phase 5.1 скопируй каждый в слот бролла `public/assets/<slug-NN>/ref-<K>.<ext>`. Субагенту в спецификацию идёт **путь к файлу** + роль (вложений Notion из твоего контекста он не видит).
- В storyboard'е по каждому референсу укажи, что именно из него берёшь (композиция / палитра / конкретный объект), и его роль.

## Несколько комментариев на одной строке

- Несколько комментариев / тред на одной строке → склей их тексты по порядку в одно описание, картинки объедини. Одна строка = один бролл.
- Резолвнутые (закрытые) комментарии пропускай, если коннектор отдаёт их статус: закрытый комментарий — снятое указание.

## Чего не делаем

- Не делаем бролл по строке, у которой есть комментарий, но нет метки в правой колонке.
- Не переносим текст комментария на экран дословно — это описание визуала, а не контент сцены.
- Не угадываем привязку, если комментарии пришли без указания строки. Лучше спросить.
