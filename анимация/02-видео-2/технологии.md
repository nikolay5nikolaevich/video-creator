# Технологии ролика «Барри попался на свою ловушку»

Ролик сделан кодом в два этапа: Blender собирает модели и считает анимацию, а кадры рендерит Three.js в браузере. Roblox Studio не использовался.

## Коротко

| Задача | Чем сделано | Файл |
|---|---|---|
| Модели, материалы, анимация, камера | Blender 4.2 как Python-модуль `bpy`, Python 3.11 | `film.py` |
| Передача сцены в браузер | GLB (геометрия) и JSON (позы всех кадров) | `сборка/web-render/scene.glb`, `timeline.json` |
| Свет и рендер кадров | Three.js 0.180.0 (WebGL) | `web-scene.html` |
| Покадровый рендер | Chrome без окна под управлением playwright-core 1.55.0, Node.js 24 | `web-render.cjs` |
| Звук | Python и numpy | `sound.py` |
| Сборка mp4 и проверка | ffmpeg из пакета imageio-ffmpeg 0.6.0 | `deliver.py` |
| Контрольные листы кадров | Python и Pillow | `review.py` |

## Картинка

**Blender без интерфейса.** `film.py` подключает Blender как библиотеку (`import bpy`) и строит всё скриптом, окно Blender не открывается.

- **Модели** собраны из примитивов: кубы со скруглёнными рёбрами (модификатор Bevel), сферы, цилиндры, торы, кривые. Барри — круглый живот, фуражка, усы, дубинка; заключённый — блочное тело в оранжевом костюме. Готовых ассетов Roblox нет, обе модели сделаны с нуля.
- **Материалы** — Principled BSDF с цветом, шероховатостью и металличностью. Картинок-текстур нет.
- **Лица** — не текстура, а отдельные 3D-детали на голове: белки, зрачки, брови и три формы рта (улыбка, недовольство, «о»). Нужный рот показывается, остальные сжимаются до нуля. Зрачки двигаются, раз в 3,77 секунды герой моргает.
- **Камера** ортографическая, без перспективных искажений.

**Анимация как функция времени.** `apply(t)` выставляет позы, лица, реквизит и камеру на любой момент. Скелета (арматуры) нет: части тела — отдельные объекты, а локти и колени получаются из отрезков между плечом, кистью, бедром и стопой.

**Экспорт.** `film.py --web` сохраняет геометрию в `scene.glb` (2,2 МБ) и проходит все 1620 кадров, записывая позицию, поворот и масштаб каждого подвижного объекта в `timeline.json` (5,9 МБ).

**Рендер в Three.js.** `web-scene.html` загружает GLB и для каждого кадра расставляет объекты по JSON. Свет настроен здесь заново, отдельно от Blender: три направленных источника (один с картами теней 2048×2048), свет неба, отражения окружения (`RoomEnvironment`), точечный тёплый свет от лавы. Тональная кривая AgX.

`web-render.cjs` поднимает локальный сервер, открывает страницу в Chrome без окна и забирает кадры JPEG по одному. Кадр родной, 1080×1920, без увеличения. По логу 1620 кадров рендерятся примерно за 3 минуты на встроенной графике Intel Iris Xe.

**Почему не рендер Blender.** Первоначально кадры выводил EEVEE, но на этой машине он тратил 3–10 секунд на кадр. Та же геометрия в WebGL выводится примерно за 0,1 секунды, поэтому финальный рендер перенесён в браузер. Blender остался инструментом моделирования и расчёта поз.

**Размытие.** В рендере его нет. При кодировании ffmpeg смешивает соседние кадры (`tmix`) на пяти коротких отрезках с быстрым движением.

## Звук

`sound.py` целиком синтезирует дорожку на numpy, внешних записей нет:

- **Музыка** — мелодия 144 удара в минуту: «деревянный» тон, бас, ударные из шума. На двух паузах музыка приглушается почти до нуля.
- **Эффекты** — восемь типов: металл, скрежет, шаг, свист, скрип, «боинг», звоночек, хруст; плюс постоянное бульканье лавы. Каждый звук расставлен по таймкоду и по панораме.

Итог — `сборка/soundtrack.wav`, 48 кГц стерео.

## Сборка и проверка

`deliver.py final` кодирует mp4: H.264 (CRF 17), 1080×1920, 60 кадров/с, цвет BT.709, небольшая прибавка контраста и насыщенности, звук AAC 256 кбит/с с нормализацией громкости до −16 LUFS. Длительность 27 секунд.

- `review.py` проверяет размер всех 1620 кадров и собирает контрольные листы с шагом 0,25 секунды.
- `deliver.py verify` декодирует готовый mp4 и проверяет длительность, разрешение, частоту кадров, наличие звука и отсутствие чёрных отрезков.

## Что ещё лежит в папке

- `ассеты/сцена/barry-animation.blend` — та же сцена с запечёнными ключами для ручной правки в Blender (`film.py --bake`).
- `ассеты/референсы/` — три ролика-референса, скачанные через yt-dlp; разбор в `разбор-референсов.md` и `качество-и-анимация.md`. В готовое видео они не входят.

## Чем этот способ ограничен

- Цепочка длинная: сцена описана в Blender, а свет и вид — в Three.js. Картинка в `.blend` и в готовом ролике различается.
- Любая правка анимации требует заново выгрузить `timeline.json`, и только потом рендерить.
- `bpy` 4.2 работает только с Python 3.11, остальной проект на 3.12.

## Что нужно на новой машине

1. Python 3.11 и пакеты в `сборка/render-tools/`: `py -3.11 -m pip install --target сборка/render-tools bpy==4.2.0 imageio-ffmpeg==0.6.0`. Оттуда же `deliver.py` берёт ffmpeg.
2. Для `sound.py`, `deliver.py` и `review.py` — обычный Python с `numpy` и `pillow`.
3. Node.js 24, затем в `сборка/web-render/`: `npm install three@0.180.0 playwright-core@1.55.0`.
4. Google Chrome по пути `C:/Program Files/Google/Chrome/Application/chrome.exe` (путь записан в `web-render.cjs`).

Порядок команд для полной пересборки записан в `производство.md`.
