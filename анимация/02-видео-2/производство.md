# Барри попался на свою ловушку

Бриф: 27 секунд, вертикальное 1080×1920, 60 кадров/с. Без диалогов. Полный сценарий из задания сохраняется; внешность заключённого — каштановые волосы, оранжевый костюм, светлые кеды.

Производство: автономная 3D-сцена Blender, оригинальные процедурные модели и анимация, монтаж камер внутри таймлайна. Предварительная проба 5–10 секунд сцены, затем весь ролик. Прямой рендер предпочтительнее захвата интерфейса Studio. При непригодности EEVEE по результатам пробы — оценить CPU-рендер. Музыка и эффекты синтезируются специально для ролика.

Последовательность: модели и локация → пробные кадры → проба движения → исправления → полный рендер → звук → сборка MP4 → визуальная и техническая проверка.

Ориентиры изучены по локальным последовательностям кадров трёх указанных роликов и двум сохранённым разборам. Исходный инструментарий автора референса неизвестен. В финальное видео кадры референсов не включаются.

География: лава в передней части коридора, безопасная площадка справа от края, камера в правой задней части, выход слева сзади. Во время погони камера остаётся по одну сторону оси движения. Наружный засов показывается отдельным планом.

Проверки: узнаваемый силуэт, захват пончика рукой, синхронность затвора и засовов, взгляд перед поворотом, отсутствие чёрных кадров, 1620 кадров при 60 fps, длительность 27 секунд, наличие стереозвука, контроль контактных листов всех сцен.

## Окончательный способ вывода

Модели, материалы и анимация создаются в Blender 4.2; геометрия экспортируется в GLB, точные трансформации каждого из 1620 кадров — в JSON. Окончательный рендер выполняется Three.js/WebGL в скрытом Chrome: **нативные 1080×1920, 60 отдельных кадров в секунду, без увеличения разрешения и без интерполяции кадров**. Используются направленный свет с тенями, заполняющий свет, отражения окружения, тёплый свет лавы и AgX. Небольшая цветокоррекция применяется при кодировании H.264; звук — стерео AAC 256 кбит/с.

Причина выбора: Intel Iris Xe выводила кадры EEVEE за 3–10 секунд; та же геометрия в WebGL выводится примерно за 0,1 секунды. Промежуточные пробы EEVEE 720p не используются в окончательном MP4. Освещение WebGL настроено отдельно; его исходник — `web-scene.html`.

Редактируемая сцена Blender сохраняется с настройкой 1080×1920 и 32 проходами для отдельного офлайн-рендера. Геометрия, материалы и ключи встроены, исходный `film.py` также вложен в файл. Детерминированный скрипт остаётся первичным источником точной покадровой анимации. Сборка bpy 4.2 не содержит Audaspace, поэтому звуковая дорожка поставляется отдельно (`сборка/soundtrack.wav`), а в MP4 включается через FFmpeg.

Музыка и Foley синтезированы специально для этого ролика в `sound.py`; внешние аудиозаписи и кадры референсов в ролике не используются. Модель Барри — самостоятельная стилизация персонажа Barry’s Prison Run, а не официальный ассет игры. Ролик не является официальным материалом Roblox.

## Воспроизведение сборки

Из этой папки, на текущей машине:

```powershell
python sound.py
py -3.11 film.py --web
node web-render.cjs probe
python deliver.py probe
node web-render.cjs final
python deliver.py final
python review.py
python deliver.py verify
```

Проект для редактора: `ассеты/сцена/barry-animation.blend`. Повторное сохранение проекта: `py -3.11 film.py --bake --samples 32`. Для альтернативного офлайн-рендера EEVEE: `py -3.11 film.py --render --batch --width 1080 --samples 32`; кадры попадут в отдельную папку `сборка/batch-final-v2-1080`. Звуковой файл начинается с первого кадра, дополнительных сдвигов не требует.

Зависимости: Python 3.11 для bpy 4.2.0; numpy и Pillow для звука и контрольных листов; imageio-ffmpeg 0.6.0; Node.js и Chrome; three 0.180.0 и playwright-core 1.55.0. Локальные Python-пакеты находятся в `сборка/render-tools`, Node-пакеты — в `сборка/web-render/node_modules`. Для переноса на другую машину нужно установить эти зависимости; путь к Chrome указан в `web-render.cjs`.

`review.py` проверяет все кадры JPEG и создаёт контрольные листы через 0,25 секунды и на границах ключевых действий. `deliver.py verify` полностью декодирует MP4 и проверяет длительность, разрешение, частоту, наличие AAC и отсутствие полностью чёрных отрезков. Визуальные решения проверяются по самим кадрам; технические проверки не заменяют художественную оценку.
